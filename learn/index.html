How the card recognizes a digit

If you can read a schematic, write a fixed-point filter and tune a controller, you already know almost all the math a neural network uses. What is missing is the story that ties it together: what the numbers mean, where they came from, and why eight bits are enough. These lessons tell it with the actual network the card runs, its actual 101 632 weights, the actual training run that produced them, and the card's actual arithmetic, down to the DSP slices.

Each scene plays like a short video: press Next (or the → key) to advance, ◀ to go back, Play all to let it run. Most scenes also let you poke at them.

Translation table. Machine-learning words for things you already know:

neuron
a dot product plus an offset, then a clamp at zero
weights
the coefficients of that dot product: filter taps
bias
the offset
layer
a matrix multiply: many dot products sharing one input
activation
a neuron's output value
ReLU
max(0, x): a half-wave rectifier
inference
running the network forward to get an answer
training
adjusting the weights from labelled examples: system identification by gradient descent
loss
the error signal training minimizes
learning rate
the step size: a gain
quantization
representing the floats as scaled integers: Q-format
MAC
multiply-accumulate, the thing a DSP slice does

Part 1

Inference: what the card computes

No learning yet. Take the weights as given (part 2 explains where they came from) and follow one digit through the network, the way the card does for every image.

Part 2

Training: where the weights came from

The network started as random numbers and scored 10 %, chance. sw/mnist/train.py turned them into the weights the card runs by showing it 60 000 labelled digits, ten times over, and nudging every weight downhill on an error signal after each batch of 128. This is that run, replayed.

Part 3

Quantization: fitting it into 8 bits

Training produced 32-bit floats. The card multiplies 8-bit integers, because an 8 × 8 multiplier is tiny and 8-bit weights move four times faster than floats. Getting from one to the other is fixed-point arithmetic, exactly as you would scale a filter for a DSP.

Part 4

On the FPGA: multipliers, pipelines and reuse

Everything above, in hardware: hw/rtl/npu_mm.v on the Artix-7's DSP48E1 slices, at 125 MHz.

Where to go next

The main page lets you draw a digit and run this network in your browser, bit for bit as the card does, and shows the commands the host sends to run it on the FPGA. The code behind every scene is in the repository: train.py (training and quantization), npu_ref.py (the card's arithmetic in Python), npu_mm.v (the engine), and lessons.py, which records the data these scenes play.

For more intuition, Grant Sanderson's 3Blue1Brown series on neural networks uses this same MNIST problem; these lessons follow its order and add the parts it leaves out: integers and hardware.
